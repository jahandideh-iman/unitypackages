# Auto-Formatting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command (`npm run format`) that formats the whole repo identically on every machine, and a required `format` CI check that keeps it formatted.

**Architecture:** CSharpier formats C#; it is pinned as a local dotnet tool. Prettier formats JSON, YAML, JS and Markdown; it is pinned as the only devDependency of a new private root `package.json`. A root `.editorconfig` supplies editor defaults and the naming rules as IDE warnings. Two npm scripts run both formatters. A new `format.yml` workflow runs the check script, and both branch rulesets require it.

**Tech Stack:** CSharpier 1.3.0 (.NET 10 SDK), Prettier 3.9.6 (Node, version from `.nvmrc`), `.editorconfig`, GitHub Actions, GitHub rulesets via `gh api`, `node:test`.

**Spec:** [`../specs/2026-09-13-auto-formatting-design.md`](../specs/2026-09-13-auto-formatting-design.md)

## Global Constraints

- **Work on `chore/auto-formatting`**, already cut from `dev` and already carrying the spec commit. It merges into `dev` only, never `master`.
- **The repo is on GitHub.** Use `gh`, never `glab`. Never prefix a git command with `cd`; use `git -C <path>`.
- **Exact versions:** CSharpier `1.3.0`, Prettier `3.9.6`, installed with `--save-exact`.
- **Prettier settings:** `printWidth: 100`, `tabWidth: 4`, `endOfLine: "auto"`, with a `tabWidth: 2` override for `package.json`, `*.yml`, `*.yaml` and `*.md`, and a further `*.md` override of `embeddedLanguageFormatting: "off"` so code blocks in docs keep their exact quoted contents.
- **CSharpier settings:** `.csharpierrc.json` contains only `"endOfLine": "auto"`.
- **`.editorconfig` sets no `end_of_line` and no `charset`.**
- **Never format:**
  - `.meta`, `.asset`, `.prefab`, `.unity`, `.anim`, `*.asmdef`
  - `ProjectSettings/`, `Packages/manifest.json`, `Packages/packages-lock.json`, `package-lock.json`
  - `Tools/ci/Tests/fixtures/`
  - `.agents/Skills/`, `.claude/`, `.qwen/`
  - `Packages/PackageBasics/Runtime/ThirdParties/`
- **The `Tools/*.mjs` scripts stay dependency-free:** no `import` of an npm package. The one test that needs Prettier runs it as a subprocess.
- **Three package folders contain spaces:** `Asset Providing`, `Scene Management`, `UI Management`. Always quote paths.
- **Job names are unique across all workflows.** The new job is `format`.
- **First-party actions (`actions/*`) are pinned by major tag; third-party actions by commit SHA.** This plan adds no third-party action.
- **The reformat PR is merged with a merge commit, never a squash.** It carries the `no-changelog` and `changelog-rewrite` labels.
- **Nothing outward-facing without the maintainer's explicit go-ahead:** pushing, opening the PR, merging, `gh api` writes to rulesets.
- **Do not name other repositories** in any committed file or commit message.
- **Heredocs eat backslashes in this environment.** Put any script with backslashes in a file.
- Commit messages end with:

```js
// ---------------------------------------------------------- formatting

// A release PR is `prepare`'s output, and it has to pass the required `format`
// check like any other PR. Prettier is the repo's one npm dependency. It runs as
// a subprocess, so this file still imports nothing but node builtins.
const PRETTIER = path.join(HERE, "..", "node_modules", "prettier", "bin", "prettier.cjs");
const PRETTIER_CONFIG = path.join(HERE, "..", ".prettierrc.json");

function prettier(repo, mode) {
    // Fail, don't skip: a skipped test is how this rule would quietly stop being enforced.
    assert.ok(fs.existsSync(PRETTIER), `Prettier is not installed at ${PRETTIER}. Run \`npm ci\` at the repo root.`);
    return spawnSync(
        process.execPath,
        [PRETTIER, mode, "--config", PRETTIER_CONFIG, "Packages/**/CHANGELOG.md", "Packages/**/package.json"],
        { cwd: repo, encoding: "utf8" },
    );
}

test("prepare's output is already formatted, so a release PR passes the format check", (t) => {
    // chain() covers both write paths: Alpha's heading is renamed, and Beta and
    // Gamma get a generated `### Changed` section and a manifest range rewrite.
    const repo = makeRepo(t, chain());
    const formatted = prettier(repo, "--write");
    assert.equal(formatted.status, 0, formatted.stdout + formatted.stderr);
    git(repo, "commit", "--allow-empty", "-am", "format");

    assert.equal(json(repo).status, 0);

    const checked = prettier(repo, "--check");
    assert.equal(checked.status, 0, checked.stdout + checked.stderr);
});
```

````markdown
Layout is owned by two formatters, run through one pair of npm scripts from the repo root:

- **Unity-written files** — `.meta`, `.asset`, `.prefab`, `.unity`, `.anim`, `.asmdef`, `ProjectSettings/`, `Packages/manifest.json`, `Packages/packages-lock.json`. Unity's next save would undo the formatting. `.asmdef` in particular is written with no final newline, and Prettier always adds one.
````
