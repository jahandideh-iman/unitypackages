# PR Test CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the repo's 9 Unity test assemblies on every same-repo pull request, reporting failures as PR annotations.

**Architecture:** A new `.github/workflows/tests.yml` runs Unity EditMode and PlayMode tests on a self-hosted Windows runner (fork PRs excluded), preserving the 2.3 GB `Library/` cache between runs. The two pieces of non-trivial logic — resolving the project's declared editor version, and analysing the editor log — live in tested PowerShell scripts under `Tools/ci/`, not inline in YAML, so they can be verified on hosted runners without a Unity install. A separate `ubuntu-latest` job turns the JUnit XML into PR annotations.

**Tech Stack:** GitHub Actions, PowerShell 5.1 (self-hosted) / PowerShell Core (hosted), Unity CLI 1.0.0-beta.3, `mikepenz/action-junit-report`.

**Spec:** [`docs/specs/2026-08-30-pr-test-ci-design.md`](../specs/2026-08-30-pr-test-ci-design.md)

## Global Constraints

- **Branch from `dev`, PR into `dev`.** `master` is release-only. Never commit to `master` directly.
- **This repo is public.** The self-hosted test job must never run code from a fork. Every task that touches the job's `if:` condition preserves `github.event.pull_request.head.repo.full_name == github.repository`.
- **Never pass `--allow-install` to `unity test`.** A missing editor must be an error, not a silent multi-gigabyte download.
- **Never pass `-e` / `--editor-path` / `--editor-version` to `unity test`.** CI runs the version in `ProjectSettings/ProjectVersion.txt` and nothing else.
- **Preserve only `Library/` between runs.** `TestResults/` and `Logs/` are job outputs and must be wiped, or a dead job republishes a stale pass.
- **Pin third-party actions by commit SHA**, never by tag. First-party `actions/*` may use major-version tags.
- **`UNITY_BURST_DISABLE_COMPILATION: "1"`** on the test job.
- **Do not modify `.github/workflows/release.yml`**, in particular its `tag` job gate.
- **Do not reference other repositories by name** in any committed file or commit message.
- **C# / PowerShell brace style: Allman** (brace on its own line), per `.agents/AGENTS.md`.

## File Structure

| File | Responsibility |
|---|---|
| `Tools/ci/Resolve-UnityEditor.ps1` | Parse the declared editor version; fail with a clear message if not installed. Pure — takes JSON as a parameter. |
| `Tools/ci/Publish-UnityLog.ps1` | Filter an editor log to its error lines, emit a bounded excerpt, recognise the Smart App Control block. Pure — takes a file path. |
| `Tools/ci/Tests/Test-CiScripts.ps1` | Fixture-driven tests for both scripts. No external test framework. |
| `Tools/ci/Tests/fixtures/` | Sample `ProjectVersion.txt`, `unity editors` JSON, and editor logs. |
| `.github/workflows/tests.yml` | Wiring only: triggers, fork gate, checkout, cache preservation, the two `unity test` calls, artefacts, reporting. |
| `.agents/AGENTS.md` | Document the CI; correct the stale Unity version claim. |

Keeping logic out of the YAML is what makes Tasks 1 and 2 testable at all. The workflow stays thin enough to read in one screen.

```powershell
#Requires -Version 5.1
# Fixture-driven tests for the CI helper scripts. No external framework:
# this must run on a bare self-hosted Windows runner and on ubuntu pwsh.
Set-StrictMode -Version Latest
$ErrorActionPreference = 'Stop'

$script:Failures = 0
$script:Root = Split-Path -Parent (Split-Path -Parent $PSScriptRoot)
$script:Fixtures = Join-Path $PSScriptRoot 'fixtures'

function Assert-Equal
{
    param($Expected, $Actual, [string] $Because)

    if ($Expected -ne $Actual)
    {
        Write-Host "  FAIL $Because"
        Write-Host "       expected: $Expected"
        Write-Host "       actual:   $Actual"
        $script:Failures++
        return
    }
    Write-Host "  ok   $Because"
}

function Assert-Match
{
    param([string] $Pattern, [string] $Actual, [string] $Because)

    if ($Actual -notmatch $Pattern)
    {
        Write-Host "  FAIL $Because"
        Write-Host "       pattern: $Pattern"
        Write-Host "       actual:  $Actual"
        $script:Failures++
        return
    }
    Write-Host "  ok   $Because"
}

# Runs a script and captures stdout plus its exit code, which is awkward in
# PowerShell: a script invoked with & does not set $LASTEXITCODE unless it
# calls exit. These scripts always call exit, so this is safe.
function Invoke-Script
{
    param([string] $Path, [hashtable] $Arguments)

    $output = & $Path @Arguments 2>&1 | Out-String
    return @{ Output = $output; ExitCode = $LASTEXITCODE }
}

Write-Host 'Resolve-UnityEditor.ps1'
$resolve = Join-Path $script:Root 'ci/Resolve-UnityEditor.ps1'

$result = Invoke-Script $resolve @{
    ProjectVersionPath = Join-Path $script:Fixtures 'ProjectVersion.txt'
    EditorsJson        = (Get-Content (Join-Path $script:Fixtures 'editors-both.json') -Raw)
}
Assert-Equal 0 $result.ExitCode 'succeeds when the declared editor is installed'
Assert-Match '6000\.5\.10f1\\Editor\\Unity\.exe' $result.Output 'reports the resolved editor path'

$result = Invoke-Script $resolve @{
    ProjectVersionPath = Join-Path $script:Fixtures 'ProjectVersion.txt'
    EditorsJson        = (Get-Content (Join-Path $script:Fixtures 'editors-missing.json') -Raw)
}
Assert-Equal 1 $result.ExitCode 'fails when the declared editor is known but not installed'
Assert-Match '::error::' $result.Output 'emits a GitHub error annotation'
Assert-Match '6000\.5\.10f1' $result.Output 'names the missing version'
Assert-Match '6000\.5\.0f1' $result.Output 'lists what is installed instead'

$result = Invoke-Script $resolve @{
    ProjectVersionPath = Join-Path $script:Fixtures 'does-not-exist.txt'
    EditorsJson        = '{"data":[]}'
}
Assert-Equal 1 $result.ExitCode 'fails when ProjectVersion.txt is absent'

Write-Host ''
if ($script:Failures -gt 0)
{
    Write-Host "$($script:Failures) assertion(s) failed."
    exit 1
}
Write-Host 'All CI script tests passed.'
exit 0
```

`Tools/ci/Resolve-UnityEditor.ps1`:

```powershell
#Requires -Version 5.1
<#
.SYNOPSIS
    Resolves the Unity editor the project declares, and fails if it is absent.

.DESCRIPTION
    CI runs the version in ProjectSettings/ProjectVersion.txt and no other. This
    script exists to turn "that editor is missing" into one clear line naming the
    version, rather than a downstream Unity CLI failure that reads like a
    compile error.

    EditorsJson is a parameter rather than something this script fetches, so it
    can be tested without a Unity install.

    NOTE: an editor can be installed and still be unable to compile -- see
    section 8 of docs/specs/2026-08-30-pr-test-ci-design.md. This check does not
    catch that; Publish-UnityLog.ps1 diagnoses it after the fact.
#>
[CmdletBinding()]
param(
    [Parameter(Mandatory)] [string] $ProjectVersionPath,
    [Parameter(Mandatory)] [string] $EditorsJson
)

Set-StrictMode -Version Latest
$ErrorActionPreference = 'Stop'

if (-not (Test-Path $ProjectVersionPath))
{
    Write-Host "::error::No ProjectVersion.txt at $ProjectVersionPath."
    exit 1
}

$versionLine = Select-String -Path $ProjectVersionPath -Pattern '^m_EditorVersion:\s*(\S+)' |
    Select-Object -First 1

if (-not $versionLine)
{
    Write-Host "::error::$ProjectVersionPath contains no m_EditorVersion line."
    exit 1
}

$declared = $versionLine.Matches[0].Groups[1].Value

try
{
    $editors = ($EditorsJson | ConvertFrom-Json).data
}
catch
{
    Write-Host "::error::Could not parse the output of 'unity editors --json': $_"
    exit 1
}

# 'location' is present only for installed editors. Matching on version alone
# would pass for an editor the Hub merely knows about.
$installed = @($editors | Where-Object { $_.PSObject.Properties.Name -contains 'location' })
$editor = $installed | Where-Object { $_.version -eq $declared } | Select-Object -First 1

if (-not $editor)
{
    $available = ($installed | ForEach-Object { $_.version }) -join ', '
    if (-not $available) { $available = '(none)' }
    Write-Host "::error::Unity $declared (from $ProjectVersionPath) is not installed on this runner. Installed: $available"
    exit 1
}

Write-Host "Resolved Unity $declared at $($editor.location)"

if ($env:GITHUB_OUTPUT)
{
    "unity-version=$declared"        | Out-File $env:GITHUB_OUTPUT -Append -Encoding utf8
    "editor-path=$($editor.location)" | Out-File $env:GITHUB_OUTPUT -Append -Encoding utf8
}

exit 0
```

`Tools/ci/Publish-UnityLog.ps1`:

```powershell
#Requires -Version 5.1
<#
.SYNOPSIS
    Summarises a Unity editor log into a CI job log, and names known environment
    failures.

.DESCRIPTION
    `unity test` streams nothing to stdout and exits silently even on success, so
    without this the job log is two command lines and nothing else.

    Only a bounded excerpt goes inline: dumping a multi-megabyte editor log costs
    the end of the trace, which is the part worth reading. The full log rides
    along as an artefact.

    Always exits 0. This is a reporting step; the caller owns the exit code.
#>
[CmdletBinding()]
param(
    [Parameter(Mandatory)] [string] $LogPath,
    [Parameter(Mandatory)] [string] $Label,
    [int] $ExitCode = 0,
    [int] $MaxLines = 200,
    [int] $TailLines = 300
)

Set-StrictMode -Version Latest
$ErrorActionPreference = 'Stop'

if (-not (Test-Path $LogPath))
{
    Write-Host "$Label -- Unity wrote no editor log at $LogPath."
    exit 0
}

# 'Exception:' with the colon on purpose: a bare 'Exception' also matches every
# Mono stack frame whose signature mentions System.Exception, which buries the
# real lines under hundreds of lines of noise.
$pattern = 'error CS\d+|Exception:|Unhandled Exception|\[Error\]|Aborting batchmode|Fatal error'
$hits = @(Select-String -Path $LogPath -Pattern $pattern)

Write-Host "----- $Label editor log: $($hits.Count) error/warning line(s) -----"
$hits | Select-Object -First $MaxLines | ForEach-Object { Write-Host "  $($_.LineNumber): $($_.Line)" }
if ($hits.Count -gt $MaxLines)
{
    Write-Host "  ... $($hits.Count - $MaxLines) more; see the uploaded artefact."
}

# A failing step is the one whose log anyone actually opens, so it gets the tail
# too -- Unity's failure summary and shutdown live there.
if ($ExitCode -ne 0)
{
    Write-Host "----- $Label failed (exit $ExitCode); last $TailLines lines -----"
    Get-Content $LogPath -Tail $TailLines | ForEach-Object { Write-Host $_ }
}

# Unity reports the Smart App Control block as 'Scripts have compiler errors.',
# which is false and costs whoever reads it an afternoon. See spec section 8.
# Both halves of the signature are required so this cannot fire on an unrelated
# [Error] line.
$logText = Get-Content $LogPath -Raw
if ($logText -match 'Bee\.Tools\.dll' -and $logText -match '0x800711C7')
{
    Write-Host "::error::Unity could not compile because Smart App Control blocked Bee.Tools.dll (0x800711C7). This is an environment block on the runner, not a compile error in this PR. See docs/specs/2026-08-30-pr-test-ci-design.md section 8."
}

Write-Host "----- end $Label editor log -----"
exit 0
```

### Task 3: The test workflow

**Files:**
- Create: `.github/workflows/tests.yml`

**Interfaces:**
- Consumes: `Tools/ci/Resolve-UnityEditor.ps1` and `Tools/ci/Publish-UnityLog.ps1` from Tasks 1–2.

- [ ] **Step 1: Write the workflow**

`.github/workflows/tests.yml`:

```yaml
name: tests

# Runs the repo's 9 test assemblies on a self-hosted Windows runner.
# See docs/specs/2026-08-30-pr-test-ci-design.md.
#
# Separate from release.yml on purpose: different runner, different trigger
# surface, and a red test should not muddy the release workflow's status.

on:
  pull_request:
  push:
    branches: [dev, master]
  workflow_dispatch:
    inputs:
      clean_library:
        description: "Discard the preserved Library/ and re-import from cold. Use this to tell a poisoned cache from broken code."
        type: boolean
        default: false

# A second push to the same PR cancels the first: Unity jobs are long and the
# runner is concurrency 1, so queued stale runs block the useful one.
concurrency:
  group: tests-${{ github.ref }}
  cancel-in-progress: true

jobs:
  # Runs everywhere, including on forks: it needs no Unity and no runner.
  script-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - name: Test the CI helper scripts
        shell: pwsh
        run: ./Tools/ci/Tests/Test-CiScripts.ps1

  test:
    needs: script-tests
    # THE SECURITY BOUNDARY. This repo is public and this runner is a physical
    # machine with a real Unity licence and a real filesystem. A pull_request
    # event from a fork checks out the contributor's code; running that here
    # would hand arbitrary write access to anyone who opens a PR.
    # Fork PRs get the ubuntu-hosted validate/pack in release.yml and nothing
    # else. Do not relax this condition.
    if: >-
      github.event_name != 'pull_request' ||
      github.event.pull_request.head.repo.full_name == github.repository
    runs-on: [self-hosted, windows, unitypackages-windows]
    timeout-minutes: 60
    env:
      # Burst's async JIT can raise errors that land inside a PlayMode test's
      # SetUp window, which makes identical commits pass and fail at random.
      # This repo builds packages, not players, so nothing here needs Burst AOT.
      # Read by BurstCompilerOptions' static ctor from the environment, not from
      # the CLI, so it cannot be silently dropped by a command-line change.
      UNITY_BURST_DISABLE_COMPILATION: "1"
      UNITY_NON_INTERACTIVE: "1"
    steps:
      # clean: false, then an explicit selective clean. actions/checkout's
      # default clean is `git clean -ffdx`, which deletes the 2.3 GB Library/
      # and buys a ~20 minute cold asset import on every single run.
      - uses: actions/checkout@v7
        with:
          clean: false

      - name: Clean, preserving the asset import cache
        shell: pwsh
        run: |
          # Only Library/. TestResults/ and Logs/ are job OUTPUTS, not caches:
          # preserving them would let a job that dies before writing results
          # upload the previous run's XML as this run's, reporting a stale pass.
          if ("${{ inputs.clean_library }}" -eq "true")
          {
            Write-Host "clean_library requested -- discarding Library/ for a cold run."
            git clean -ffdx
          }
          else
          {
            git clean -ffdx -e Library/
          }
          git reset --hard

      - name: Resolve the Unity editor
        id: editor
        shell: pwsh
        run: |
          $json = unity editors --json | Out-String
          ./Tools/ci/Resolve-UnityEditor.ps1 `
            -ProjectVersionPath ProjectSettings/ProjectVersion.txt `
            -EditorsJson $json

      - name: EditMode tests
        id: editmode
        shell: pwsh
        run: |
          # No -e and no --allow-install, deliberately: `unity test` already
          # defaults to the version in ProjectVersion.txt, and --allow-install
          # would turn a missing editor into a silent multi-GB download.
          unity test --mode EditMode `
            --output TestResults/editmode-results.xml `
            --report-format nunit,junit `
            --junit-output TestResults/editmode-junit.xml `
            --timeout 1800
          $code = $LASTEXITCODE

          # Copied aside immediately: the PlayMode editor overwrites
          # Logs/Editor.log, so capturing once at the end loses this one.
          if (Test-Path Logs/Editor.log)
          {
            Copy-Item Logs/Editor.log Logs/editmode-editor.log -Force
          }
          ./Tools/ci/Publish-UnityLog.ps1 -LogPath Logs/editmode-editor.log -Label EditMode -ExitCode $code

          # 8 = tests ran and failed. 6 = the run never produced results.
          # Collapsing them into "nonzero" is what sends someone debugging a
          # test that never ran.
          if ($code -eq 8)
          {
            Write-Host "::error::EditMode suite is red. Open the test report."
            exit 8
          }
          if ($code -ne 0)
          {
            Write-Host "::error::EditMode run produced no results (exit $code) -- build or environment failure. Open the editor log artefact."
            exit $code
          }

      - name: PlayMode tests
        id: playmode
        # always() so a red EditMode suite still reports PlayMode rather than
        # hiding a second, independent failure behind the first.
        if: always() && steps.editmode.conclusion != 'skipped'
        shell: pwsh
        run: |
          unity test --mode PlayMode `
            --output TestResults/playmode-results.xml `
            --report-format nunit,junit `
            --junit-output TestResults/playmode-junit.xml `
            --timeout 1800
          $code = $LASTEXITCODE

          if (Test-Path Logs/Editor.log)
          {
            Copy-Item Logs/Editor.log Logs/playmode-editor.log -Force
          }
          ./Tools/ci/Publish-UnityLog.ps1 -LogPath Logs/playmode-editor.log -Label PlayMode -ExitCode $code

          if ($code -eq 8)
          {
            Write-Host "::error::PlayMode suite is red. Open the test report."
            exit 8
          }
          # There are no PlayMode test assemblies yet -- all 9 are
          # includePlatforms: ["Editor"]. This step is here so the first
          # PlayMode test written is covered automatically rather than silently
          # unrun. An empty run that still produced a results file is a pass;
          # only a run that produced nothing at all is a failure.
          if ($code -ne 0)
          {
            if (Test-Path TestResults/playmode-results.xml)
            {
              Write-Host "::notice::PlayMode exited $code but produced results -- treating as an empty suite. If this repo now has PlayMode tests, investigate."
              exit 0
            }
            Write-Host "::error::PlayMode run produced no results (exit $code) -- build or environment failure. Open the editor log artefact."
            exit $code
          }

      - uses: actions/upload-artifact@v7
        if: always()
        with:
          name: test-results
          path: |
            TestResults/
            Logs/
          retention-days: 30
          # An empty PlayMode run may legitimately produce no XML; do not turn
          # that into a second, confusing warning.
          if-no-files-found: ignore
```

### Task 4: PR annotations

**Files:**
- Modify: `.github/workflows/tests.yml` (append a `report` job)

**Interfaces:**
- Consumes: the `test-results` artefact produced by Task 3's `test` job.
- Produces: nothing downstream.

The reporter runs on `ubuntu-latest` rather than the self-hosted runner so that a third-party action holding `checks: write` never executes on the physical machine. In a public repo with a self-hosted runner that separation is worth the twenty seconds it costs.

- [ ] **Step 1: Resolve the action's commit SHA**

Run: `gh api repos/mikepenz/action-junit-report/git/ref/tags/v5 --jq .object.sha`
Expected: a 40-character SHA. Use it verbatim in Step 2 — **do not** substitute `@v5`. A tag can be moved by its owner; a SHA cannot.

- [ ] **Step 2: Append the report job**

Append to `.github/workflows/tests.yml`:

```yaml
  report:
    needs: test
    # always(), so a red suite still reports. Without this the annotations
    # vanish precisely when they are the thing you wanted.
    if: always() && needs.test.result != 'skipped'
    runs-on: ubuntu-latest
    permissions:
      contents: read
      checks: write
      pull-requests: write
    steps:
      - uses: actions/download-artifact@v7
        with:
          name: test-results
          path: artifacts
        continue-on-error: true

      # Pinned by SHA, not tag: this is a third-party action with checks: write
      # in a public repo, and a tag can be moved by its owner.
      - name: Publish test report
        uses: mikepenz/action-junit-report@<SHA-FROM-STEP-1>
        if: always()
        with:
          report_paths: 'artifacts/TestResults/*-junit.xml'
          check_name: 'Unity tests'
          fail_on_failure: true
          require_tests: false
```

`require_tests: false` matters: with no PlayMode assemblies yet, one of the two XML files may report zero tests, and `true` would fail the job for it.
